1. Business Context & Architectural Pivot (ADR-0004)

Initially, drmpack considered implementing a native Rust MP4 container parser and AES-128 ciphers (ADR-0002). However, strict hardware CDMs (Apple FairPlay, Google Widevine L1, Microsoft PlayReady on SmartTVs) strictly reject ISO-BMFF streams with minute discrepancies in NALU framing, subsample byte offsets, or slice headers without providing debug logs.

Per ADR-0004, drmpack pivoted to orchestrating the industrial GPAC filter engine as an isolated, persistent subprocess over anonymous Unix pipes. This guarantees 100% hardware CDM compliance, native LL-HLS (`EXT-X-PART`) and CMAF chunking support, and isolates C-library memory safety from media-server.

2. Domain Type System & Key Management

drmpack models DRM concepts using strong domain types:

  • KeyID (KID): 16-byte UUID identifying a content key.
  • ContentKey: 16-byte AES key mapped to a specific QualityTier (e.g. SD, HD, 4K) and TrackType (Audio / Video).
  • KeySet: In-memory cache of resolved ContentKeys and system-specific PsshData.
  • KeyProvider: Pluggable async trait for key acquisition (RawKeyProvider for tests, CPIX, Axinom, SPEKE v2).

3. GPAC Common Encryption XML Generator (`drm.xml`)

Rather than transforming MP4 boxes in Rust, GpacDrmXmlGenerator dynamically constructs an XML configuration for GPAC's cecrypt filter:

  • Defines CrypTrack elements matching each Rendition's track ID.
  • Sets scheme_type="cenc" (AES-CTR) or scheme_type="cbcs" (AES-CBC 1:9 pattern).
  • Injects multi-DRM DRMInfo blocks containing base64-encoded PSSH boxes for Widevine, FairPlay, and PlayReady.

4. Subprocess Pipe IPC & Watchdog Monitoring

GpacProcess manages the child process lifecycle via tokio::process::Command:

  • stdin: Stdio::piped() transfers raw fMP4 media bytes without disk writes.
  • stderr: Continuously buffered into memory and streamed to tracing logs.
  • Watchdog: Background Tokio task monitors heartbeat pings from push_segment(). If input stalls beyond session_timeout, GPAC is terminated safely to prevent orphaned processes.

5. Zero-I/O Ramdisk Manifest & Chunk Distribution (ADR-0005)

Per ADR-0005, GPAC's dasher filter writes manifests and CMAF partial segments directly into shared memory (/dev/shm on Linux, or system tempfs). This guarantees sub-millisecond manifest read latency for edge HTTP servers and eliminates physical SSD wear under 200ms manifest refresh cycles.

6. PackagingSession Coordination & Cleanup Lifecycle

PackagingSession exposes clean, typed path accessors:

  • hls_manifest_path() ➔ returns <output_dir>/live.m3u8
  • dash_manifest_path() ➔ returns <output_dir>/live.mpd
  • cleanup().await ➔ deletes the Ramdisk directory after the draining window completes.
  • auto_cleanup ➔ optional flag to clean Ramdisk immediately on close().

7. End-to-End Testing Seam Verification

Tests exercise the complete stack at the single public seam: PackagingSession. tests/tracer_e2e.rs pushes a sample fMP4 stream, triggers GPAC packaging, and asserts that generated Ramdisk manifests and init segments contain valid Widevine PSSH boxes verified via tests/common/find_box.
