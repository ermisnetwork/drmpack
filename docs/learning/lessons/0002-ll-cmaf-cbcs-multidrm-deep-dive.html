1. Sơ Đồ Toàn Cảnh Kiến Trúc Data Plane & Luồng Dữ Liệu

drmpack là thư viện Rust chạy in-process bên trong media-server. Nhiệm vụ của nó là nhận các media segment (muxed fMP4) dạng bytes, mã hóa theo chuẩn bảo mật phần cứng (Widevine L1, Apple FairPlay), đóng gói phân mảnh Low-Latency CMAF, và xuất trực tiếp vào bộ nhớ dùng chung Ramdisk (/dev/shm) mà không tiêu tốn bất kỳ I/O đĩa vật lý nào.

2. Giải Phẫu Từng Dòng: Subprocess & Đột Phá Unbuffered Pipe (src/gpac/process.rs)

File này chịu trách nhiệm sinh câu lệnh CLI chuẩn xác cho engine lọc của GPAC và quản lý stdin/stderr pipe qua tokio::process.

Dòng 58-60 
// 1. Input filter: read continuous fMP4 from stdin pipe without memory buffering delay
args.push("-i".into());
args.push("stdin:ext=mp4:mstore_samples=0:mstore_purge=0".into());

Bản chất kỹ thuật:

  • stdin: Bảo GPAC bộ lọc đầu vào (filter pin) lắng nghe từ Standard Input (file descriptor 0).
  • ext=mp4: Vì pipe là dòng byte vô hướng không có phần mở rộng file, cờ này bắt buộc GPAC kích hoạt demuxer ISOBMFF (mp4dmx).
  • Đột phá mstore_samples=0:mstore_purge=0: Mặc định, GPAC demuxer khi đọc từ stream bộ nhớ sẽ đệm lại 50 samples (tương đương 1.6 giây video 30fps) và 50,000 bytes trước khi xả bảng mẫu (sample table) sang filter mã hóa. Trong kịch bản Low-Latency (chunk 200ms = 6 frames), việc đệm 50 frames làm đóng băng toàn bộ pipeline; GPAC không tạo ra file nào cho đến khi pipe bị đóng! Thiết lập =0 ép GPAC xả dữ liệu ngay khi vừa đọc được từng frame, đảm bảo sub-second chunk xuất hiện tức thì trong Ramdisk.
Dòng 62-63 
// 2. Encryption filter: cecrypt with generated DRM XML
args.push(format!("cecrypt:cfile={}", self.drm_xml_path.display()));

Bản chất kỹ thuật:

  • Gắn filter cecrypt vào chuỗi xử lý. Tham số cfile chỉ đến file cấu hình XML DRM tạm trong Ramdisk. Filter này sẽ đọc KID, Key, scheme, và pattern để mã hóa từng frame payload NALU trước khi chuyển tiếp sang module đóng gói manifest.
Dòng 66-83 
let manifest_path = self.output_dir.join("live.mpd");
let mut dasher_opt = format!(
    "{}:dual:profile=live:dmode=dynamic:segdur={}:pssh=mv",
    manifest_path.display(),
    self.segment_duration
);

if self.latency_mode == LatencyMode::LowLatency {
    let asto = (self.segment_duration - self.chunk_duration).max(0.1);
    dasher_opt.push_str(&format!(
        ":cdur={}:asto={:.1}:llhls=br:cmaf=cmfc",
        self.chunk_duration, asto
    ));
}

args.push("-o".into());
args.push(dasher_opt);

Bản chất kỹ thuật:

  • :dual: Lệnh cho filter dasher tạo đồng thời cả manifest DASH (live.mpd) và HLS (live.m3u8) từ một luồng media duy nhất, tiết kiệm 50% CPU so với việc chạy 2 tiến trình độc lập.
  • :profile=live:dmode=dynamic: Chế độ live stream phân mảnh thời gian thực; manifest liên tục cập nhật timeline trượt (sliding window).
  • :pssh=mv: Ghi các hộp PSSH vào movie header (moov) của Init segment, bắt buộc cho chuẩn CMAF và DASH.
  • :cdur=0.2: Phân mảnh CMAF sub-second (200ms mỗi chunk).
  • :asto=0.8: Availability Time Offset. Báo cho DASH client biết rằng client được phép gửi HTTP request tải chunk sớm trước 0.8 giây so với thời điểm segment 1 giây hoàn thành.
  • :llhls=br: Kích hoạt Apple Low-Latency HLS ở chế độ Byte-range. GPAC sẽ xuất các partial chunks dưới dạng byte ranges trỏ vào file media chính và thêm các thẻ #EXT-X-PART vào playlist HLS.

3. Giải Phẫu Từng Dòng: Multi-DRM XML Generator & FairPlay Signaling (src/gpac/xml.rs)

File này chuyển dịch từ điển miền KeySet sang định dạng XML đặc thù mà filter cecrypt của GPAC yêu cầu.

Dòng 63-73 
let scheme_str = match config.scheme {
    EncryptionScheme::Cenc => "cenc",
    EncryptionScheme::Cbcs => "cbcs",
    EncryptionScheme::Dual => "cenc",
};

writeln!(xml, r#"<GPACDRM type="{}">"#, scheme_str).unwrap();

Bản chất kỹ thuật:

  • Trước đây code hardcode <GPACDRM type="CENC">. Khi thuộc tính này là CENC, GPAC sẽ ép thuật toán AES-CTR bất kể thuộc tính trên track là gì.
  • Bằng cách truyền động scheme_str, khi mã hóa Apple FairPlay (EncryptionScheme::Cbcs), thẻ gốc trở thành <GPACDRM type="cbcs">, báo cho GPAC kích hoạt cipher AES-CBC và tự động chuyển HLS key method sang #EXT-X-KEY:METHOD=SAMPLE-AES.
Dòng 187-220 
fn build_hls_info(pssh_list: &[PsshData], key: &ContentKey) -> Result<Option<String>> {
    if pssh_list.is_empty() {
        return Ok(None);
    }

    let mut parts = Vec::new();
    for pssh in pssh_list {
        if pssh.drm_system == DrmSystem::FairPlay {
            let skd_uri = if !pssh.data.is_empty() && pssh.data.starts_with(b"skd://") {
                String::from_utf8_lossy(&pssh.data).to_string()
            } else {
                format!("skd://{}", key.kid.0.hyphenated())
            };
            parts.push(format!(
                r#"URI="{}",KEYFORMAT="com.apple.streamingkeydelivery",KEYFORMATVERSIONS="1""#,
                skd_uri
            ));
        } else {
            let pssh_box = build_pssh_box(pssh)?;
            let uri = BASE64_STANDARD.encode(pssh_box);
            parts.push(format!(
                r#"URI="data:text/plain;base64,{}",KEYFORMAT="urn:uuid:{}",KEYFORMATVERSIONS="1""#,
                uri,
                format_uuid(&pssh.system_id)
            ));
        }
    }

    Ok(Some(parts.join(",")))
}

Bản chất kỹ thuật:

  • Đặc thù của Apple FairPlay: Trình duyệt Safari và thiết bị iOS từ chối giải mã nếu thẻ #EXT-X-KEY mang format PSSH base64. FairPlay bắt buộc phải có KEYFORMAT="com.apple.streamingkeydelivery" và URI giao thức skd://<KID> để trình phát AVPlayer kích hoạt delegate lấy Server Playback Context (SPC).
  • Cú pháp Delimiter ,URI= của GPAC: Để GPAC xuất nhiều dòng #EXT-X-KEY (cho cả FairPlay và Widevine/PlayReady) trong cùng một rendition, các định nghĩa phải nằm trong cùng thuộc tính hlsInfo và ngăn cách nhau bởi delimiter ,URI=. Vì mỗi phần tử trong mảng parts bắt đầu bằng URI="...", việc nối bằng dấu phẩy parts.join(",") tạo ra chính xác chuỗi: hlsInfo='URI="skd://...",KEYFORMAT="com.apple...",URI="data:text...",KEYFORMAT="urn:uuid..."'.

Dòng 264-272 
pub async fn push_segment(&mut self, segment: Segment) -> Result<()> {
    if self.closed {
        return Err(DrmpackError::Session("PackagingSession is closed".into()));
    }
    self.ping_heartbeat();

    let mut gpac = self.gpac.lock().await;
    gpac.write_data(&segment.data).await
}

Bản chất kỹ thuật:

  • Segment bytes từ media-server được ghi thẳng vào stdin pipe của GPAC child process qua tokio::io::AsyncWriteExt::write_all và flush(). Dữ liệu chỉ nằm trên trang bộ nhớ đệm (kernel pipe buffer) của Linux, hoàn toàn không chạm xuống đĩa cứng vật lý.

5. Sơ Đồ Cấu Trúc Hộp ISO-BMFF (MP4 Box Hierarchy) & Giải Mã Phần Cứng

Phần cứng CDM trên thiết bị (Apple Secure Enclave, Android TEE) phân tích dòng MP4 bằng cách duyệt cây cấu trúc hộp nhị phân (Boxes/Atoms). Bất kỳ sự sai lệch nào về cấu trúc hộp sẽ dẫn đến lỗi từ chối giải mã (Black screen hoặc DRM decode error).

FILE 1: stdin_dashinit.mp4 (Initialization Segment - Khởi tạo bộ giải mã) └── ftyp (File Type: "iso6", "cmfc") └── moov (Movie Metadata Box) ├── mvhd (Movie Header: timescale, duration = 0 for live) ├── trak (Track Definition) │ ├── tkhd (Track Header: width, height, track ID = 1) │ └── mdia (Media Box) │ ├── mdhd (Media Header) │ └── minf (Media Information) │ └── stbl (Sample Table Box) │ └── stsd (Sample Description: codec profile) │ └── encv (Encrypted Video Sample Entry - thay thế cho 'avc1') │ └── sinf (Protection Scheme Information Box) │ ├── frma (Original Format: data_format = "avc1") │ ├── schm (Scheme Type Box) │ │ ├── scheme_type: "cenc" (AES-CTR) hoặc "cbcs" (AES-CBC) │ │ └── scheme_version: 0x00010000 │ └── schi (Scheme Information Box) │ └── tenc (Track Encryption Box) ⭐ [QUYẾT ĐỊNH MÃ HÓA] │ ├── default_IsEncrypted: 0x01 │ ├── default_IV_size: 16 bytes │ ├── default_KID: [16 bytes UUID] │ └── default_crypt_byte_block / default_skip_byte_block: │ (Nếu CBCS: 1:9 pattern -> byte giá trị 0x19) ├── pssh (Protection System Specific Header - Widevine: SystemID 0xedef8ba9...) └── pssh (Protection System Specific Header - FairPlay: SystemID 0x94ce86fb...) FILE 2: stdin_dash1.m4s (Media Segment - Dữ liệu video thực tế) ├── styp (Segment Type: "msdh", "msix") └── moof (Movie Fragment Box - Đóng gói từng phần media) ├── mfhd (Movie Fragment Header: sequence_number) └── traf (Track Fragment Box) ├── tfhd (Track Fragment Header: track_ID, base_data_offset) ├── tfdt (Track Fragment Base Media Decode Time: mốc thời gian phát) ├── trun (Track Fragment Run: độ dài, kích thước từng sample video) ├── senc (Sample Encryption Box) ⭐ [THÔNG TIN VECTOR IV & SUBSAMPLE] │ └── chứa IV (Initialization Vector) cho từng frame │ └── Subsample encryption table: [bytes_clear, bytes_encrypted] ├── saiz (Sample Auxiliary Information Sizes Box) └── saio (Sample Auxiliary Information Offsets Box) └── mdat (Media Data Box) └── [Payload các khối NALU video đã bị mã hóa AES 1:9 hoặc full CTR]
Tại sao hộp tenc và schm quyết định sự thành bại của Ticket 03?
Khi Safari nhận được stream, trình giải mã đọc hộp schm trong moov. Nếu thấy chuỗi cbcs, nó đọc tiếp hộp tenc để kiểm tra byte pattern (1 block mã hóa 16 bytes, 9 blocks bỏ qua 144 bytes). Nếu các trường này chuẩn xác, CDM của Apple sẽ chuyển sang chế độ AES-CBC phần cứng và dùng KID để gửi request lấy license qua URI skd:// trong HLS.

File test e2e là nơi duy nhất kiểm chứng toàn bộ sự tích hợp giữa Rust, Kernel Pipe và binary GPAC thực tế trên máy chủ.
